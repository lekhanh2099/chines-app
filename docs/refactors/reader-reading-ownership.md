## Contracts to lock before implementation gates

- Zod owns model types; Reader accepts raw string, string arrays, structured segment arrays (including aliases), and portable documents. Facade owns cooker/provider initialization.
- Cooker preserves source structure/IDs/pinyin, generates deterministic runtime-only IDs, rejects duplicates/broken references, and separates generation from display. Conflicting aliases must not silently select one value.
- Runtime stores only normalized reactive content/navigation/playback/UI. Services, callbacks and DOM registry remain outside reactive state.
- Commands identify segments by ID. Speech resolves exactly once on completion/cancellation, rejects errors, and cannot leave pending requests on stop/unmount/replacement. Shared-service ownership must be tested with two Reader instances.
- Same-document replacement preserves a surviving active ID; different-document replacement resets session. Changed/removed playback content cancels audio and stale callbacks.
- Pronunciation analysis is not repeated by cooker and renderer. Shared pure implementation must not import HanziHome.
- Existing learning settings remain externally controlled for HanziHome; standalone display is local. No mirrored persisted owner.
- Standalone proof precedes production Reader UI migration. Persisted API migration remains phase 16; legacy endpoint removal requires compatibility evidence.

- reader.schemas.ts combines generic rows/exercises and Humanities content. Move Humanities-owned schemas in phase 12 without weakening exercise payload coverage in phase 8.
- reader-state.schemas.ts/API combine Reader/Daily/Personal and practice/learning-loop state. Preserve their distinct persistence semantics while splitting; learning-loop repository belongs with its existing HanziHome feature.
- Annotation repository validates Business Chinese targets using its adapter and static content. Keep source-specific target validation at integration ownership; moving imports alone will retain coupling.
- ReaderDocumentStudy and study hooks combine learning preferences, practice attempts and resource user state. Generic engine must receive callbacks/services; repositories remain outside it.
- Content repository reads the static studio package. Do not replace it with DB reads during relocation.
- PDF currently composes Reading workspaces and assets; target reading/pdf. No new top-level PDF feature is required.
- Daily schemas include legacy browser migration inputs. Preserve them until migration compatibility is proven.
- Existing server/client boundaries and query keys must be traced at each move. Inventory assigns ownership; it does not authorize wire-format or persistence changes.
